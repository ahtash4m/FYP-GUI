# Acne Classification FYP — GUI Project Handoff

This document describes **everything that exists today** in the **`D:\FYP-GUI`** frontend repository: goals, tooling, folder layout, **all routes**, environment variables, the **mock-versus-real API strategy**, and **exact next steps** for integrating a Flask backend and MySQL. It is written so a **human programmer** or an **LLM** can onboard without prior chat context.

---

## 1. Project purpose (what this GUI is for)

This repository implements the **browser GUI** for a Final Year Project aligned with the university scope/SRS/SDD:

- **Working title:** Web application for **acne classification** and **OTC (over-the-counter) suggestion** from **facial images**.
- **Patient experience:** sign in → upload JPEG/PNG → see a “processing” state → view **classification + confidence + OTC routine** + disclaimers → browse **scan history**.
- **Admin experience:** overview metrics + chart + activity table → **user management** table → **treatment rules** CRUD (maps AI labels to OTC text) → **settings** (toggles, language, model version display, confidence threshold slider, backup button placeholder).
- **Explicit non-goals in the UI (per SRS):** no pharmacy checkout, no Rx-only drugs, no live video telemedicine. Copy should keep reinforcing **non-diagnostic / triage / educational** positioning.

The GUI is intentionally built with **API placeholders** so Flask + TensorFlow + MySQL can be connected later **without rewriting screens**.

## 8. Environment variables

Defined in **`.env.example`** and typed in **`src/vite-env.d.ts`**.

| Variable | Typical value | Behavior |
|----------|---------------|----------|
| `VITE_USE_MOCK_API` | `true` | **Default behavior if unset:** feature modules **do not** call the network for domain operations; they use mocks / local mutation stores. |
| `VITE_USE_MOCK_API` | `false` | Feature modules call **`fetch`** against **`/api/...`** (same origin in dev, proxied to Flask). |
| `VITE_API_BASE_URL` | *(empty)* | If empty, `apiUrl()` in `client.ts` uses **relative** paths like `/api/...` (recommended with Vite proxy). If set to an absolute URL, requests go there instead (useful if API is on another host during dev — CORS must be configured server-side). |
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:5000` | **Dev only:** Vite proxy target for `/api`. Flask often uses `5000`; your backend may differ — change this, not the React code. |

**Security note:** Anything prefixed with `VITE_` is **exposed to the browser bundle**. Never put secrets (private keys, DB passwords) in `VITE_*` variables.

## 9. Application entry and provider hierarchy

### 9.1 Entry

- **`src/main.tsx`** mounts React to `#root`.
- Wraps the tree in **`React.StrictMode`** (development double-invocation of some effects is intentional).

### 9.2 Provider nesting (top → bottom)

```
QueryClientProvider   (src/providers/query-provider.tsx)
  └─ AuthProvider     (src/providers/auth-provider.tsx)
       ├─ RouterProvider (src/router.tsx → AppRouter)
       └─ Toaster      (sonner, in src/providers/app-providers.tsx)
```

**`src/providers/app-providers.tsx`** composes `QueryProvider` + `AuthProvider` + `Toaster`.

**Why this order matters**

- **React Query** must wrap any component using `useQuery` / `useMutation`.
- **Auth** must wrap **routes** that call `useAuth()` (including `RootRedirect` in `router.tsx`).
- **Router** must be inside **Auth** so guards and redirects can read the authenticated user.

## 11. Auth behavior (current implementation)

### 11.1 Mock authentication rules

Implemented in **`src/features/auth/auth.api.ts`** and **`src/pages/login-page.tsx`**:

- **`login(email, password, devRoleHint?)`**
  - If **`VITE_USE_MOCK_API`** is not `"false"` / `"0"`:
    - Simulates latency (~450ms).
    - If `devRoleHint` is passed, uses that role.
    - Else if email contains substring **`admin`** (case-insensitive) → **`role: "admin"`**.
    - Else → **`role: "patient"`**.
  - Returns an `AuthUser` object; **`AuthProvider`** stores it.
- **Register** always yields a **patient** in mock mode.

**Convenience UI:** Login page includes **“Admin demo (mock)”** button → calls `login("admin@demo.local", "password", "admin")`.

### 11.2 Persistence

- **`src/providers/auth-provider.tsx`** reads/writes JSON to **`localStorage`** key **`acne_classification_auth_user_v1`**.
- This is a **development convenience**, not a security model. Replace with **httpOnly cookies** or **secure token storage** when Flask auth exists.

### 11.3 Logout

- Mock: short delay.
- Real (future): `POST /api/auth/logout` via `postJson` in `auth.api.ts`.

## 12. API layer — how mocks and real HTTP are separated

### 12.1 Decision point

**`src/lib/api/config.ts`**

- `useMockApi()` returns **true** unless `VITE_USE_MOCK_API` is exactly `"false"` or `"0"`.

### 12.2 Low-level HTTP helpers

**`src/lib/api/client.ts`**

- `getJson`, `postJson`, `patchJson`, `deleteJson`, `postFormData`.
- Uses `credentials: "include"` to be compatible with **cookie-based** sessions later.
- Throws **`ApiError`** with `status` + parsed body on non-2xx.

### 12.3 Feature modules (the only place screens should import)

| Module file | Responsibility |
|-------------|------------------|
| `src/features/auth/auth.api.ts` | `login`, `register`, `logout`. |
| `src/features/scans/scans.api.ts` | `uploadScan` (multipart), `getScan`, `listScans`. |
| `src/features/admin/admin.api.ts` | Stats, activity, users, treatments CRUD, settings, backup stub. |

**Rule for future work:** UI components and pages should **not** call `fetch` directly except in rare cases — go through these modules so mock/real switching stays centralized.

### 12.4 Mock data sources

**`src/mocks/fixtures.ts`** contains static arrays/objects used by mock branches.

**Admin treatments in mock mode:** `admin.api.ts` keeps a **module-level mutable `treatmentStore` array** so create/update/delete works across interactions without a server.

**Admin settings in mock mode:** similarly uses **`settingsStore`**.

## 16. Important implementation detail — scan upload + React Strict Mode

**File:** `src/pages/patient-processing-page.tsx`

React 18 **StrictMode** in development can mount/unmount/mount effects. To avoid **duplicate `uploadScan` mutations**, the flow uses:

1. A per-navigation **`nonce`** (`crypto.randomUUID()`) passed from the dashboard in router location state alongside the **`File`**.
2. A **`sessionStorage`** key `acne-scan-mutate:<nonce>` so **`mutate(file)`** runs only once per nonce.

Cosmetic timers may still reset on remount; the important part is **no double POST** to the future backend.

## 18. How a programmer should take this to the next phase (recommended order)

1. **Freeze API contracts** with your Flask team: paths, JSON field names, auth mechanism (**cookies vs Bearer**), error format.
2. Implement Flask routes under **`/api`** (or change `*.api.ts` to match your prefix).
3. Set **`.env`**: `VITE_USE_MOCK_API=false`, confirm **`VITE_API_PROXY_TARGET`** points to Flask in dev.
4. Replace **`localStorage` auth** with real session handling; update **`api/client.ts`** to attach tokens if using Bearer.
5. **Multipart:** confirm the multipart field name matches (`image` today).
6. **Scan results:** decide whether image URLs are **blob URLs**, **S3 URLs**, or **server file routes**; update `ScanResult.imageUrl` handling accordingly.
7. **Pagination:** replace disabled buttons with query params (`?page=` / `?cursor=`) + TanStack Table if needed.
8. **Testing:** add Vitest + React Testing Library (not set up yet).
9. **CI:** add GitHub Actions to run `npm run build` on push (not set up yet).
